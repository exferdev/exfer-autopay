exfer-autopay API

HTTP payment queue service for the Exfer blockchain.
Accepts payment requests, batches them, broadcasts to the network, and notifies via webhook on settlement.

BASE URL https://pay.exfer.dev
ℹ All amounts are in EXFER (human-readable string, e.g. "1.5"). Timestamps are Unix milliseconds. All responses are JSON.
Authentication

Every request must include an API key in the Authorization header.

Header
Authorization: Bearer <API_KEY>
Example
curl https://pay.exfer.dev/health \
  -H "Authorization: Bearer your-api-key"

Returns 401 Unauthorized if the key is missing or incorrect.

Payment Status
StatusDescription
pendingWaiting to be included in the next batch
processingTransaction broadcast; awaiting on-chain confirmation
confirmedConfirmed on chain ✅
failedRetries exhausted — permanently failed ❌
ℹ Up to MAX_RETRIES (default 3) broadcast attempts are made before a payment is marked failed. Even if failed — always verify on-chain using tx_id if present.
Endpoints
POST /pay

Submit a payment request. Returns immediately with a pending status. The payment is processed asynchronously by the flusher.

Request Body
FieldTypeDescription
tostringrequiredRecipient address (64-char hex)
amountstringrequiredAmount in EXFER, e.g. "1.5"
walletstringoptionalWallet ID. Defaults to the first wallet in wallets.json
refstringoptionalYour business order ID for later lookup via GET /ref/:ref
webhookstringoptionalURL to POST when the payment reaches a terminal state
Request
curl -X POST https://pay.exfer.dev/pay \
  -H "Authorization: Bearer your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "to":      "92bdb00612e9522126dd1ae837c53cd1e5bb14e64923e2f6ed602d7268040d05",
    "amount":  "1.5",
    "wallet":  "main",
    "ref":     "order_001",
    "webhook": "https://your.server/payment/callback"
  }'
Response 202
{
  "id":         "pay_eba99ba6f4a16478",
  "status":     "pending",
  "ref":        "order_001",
  "wallet":     "main",
  "to":         "92bdb006...040d05",
  "amount":     "1.5",
  "created_at": 1780553055604
}
GET /status/:id

Get the current status of a payment by its ID.

ParamTypeDescription
idstringrequiredPayment ID returned by POST /pay
Response 200
{
  "id":           "pay_eba99ba6f4a16478",
  "ref":          "order_001",
  "status":       "confirmed",
  "wallet":       "main",
  "to":           "92bdb006...040d05",
  "amount":       "1.5",
  "tx_id":        "b9be9396...d998d",    // null if not yet broadcast
  "fee":          "0.00000069",            // null until confirmed
  "error":        null,                     // set on failure
  "retries":      0,
  "created_at":   1780553055604,
  "confirmed_at": 1780553068000             // null until confirmed
}
GET /ref/:ref

Look up all payments that share a business ref. Useful when one order triggers multiple payments.

Response 200
{
  "count": 1,
  "payments": [ /* array of Payment objects */ ]
}
GET /health

Service health check. Returns all loaded wallets with per-wallet queue counts. Use for monitoring.

Response 200
{
  "ok": true,
  "wallets": [
    {
      "id":      "main",
      "address": "90444e23...c3541",
      "queue": {
        "pending": 0, "processing": 0,
        "confirmed": 12, "failed": 0
      }
    }
  ],
  "total": { "pending": 0, "processing": 0, "confirmed": 12, "failed": 0 }
}
Webhook Callbacks

When a payment reaches confirmed or failed, a POST is sent to the webhook URL specified in the original request. Retried up to 5 times with exponential backoff (2s / 4s / 8s / 16s / 32s).

Confirmed
{
  "id":           "pay_eba99ba6f4a16478",
  "ref":          "order_001",
  "status":       "confirmed",
  "tx_id":        "b9be9396...d998d",
  "fee":          "0.00000069",
  "created_at":   1780553055604,
  "confirmed_at": 1780553068000
}
Failed
{
  "id":           "pay_eba99ba6f4a16478",
  "ref":          "order_001",
  "status":       "failed",
  "error":        "No confirmed UTXOs available",
  "created_at":   1780553055604,
  "confirmed_at": null
}
⚠ A failed status means the service gave up retrying the broadcast. If tx_id is present, verify on-chain directly — the transaction may still confirm.
